# Agent ETA：Claude Code 的"还要多久 / 我能不能先离开"插件

[English](plugin.md)

> **先读这个。** 本页是插件的使用说明。做这个插件时学到的东西——包括为什么“可离开”窗口天生很短（80% 把握下约 1–2 分钟）、在不同用户身上实际有多可靠——在[研究报告](../README.zh-CN.md)里。简单说：它适合看清 agent 的时间花在哪里、给出诚实的时长区间；它解放不了大块时间。


状态栏会实时显示两件事：**Claude 还要多久做完**，以及**你可以放心离开多久**。
估计值从你自己的历史里学出来。整个插件不调用模型，不往上下文注入内容，也不消耗 token。

```
⏱ 3:12 │ 完成 ~4–9m │ 可离开 ~3m → 14:52 │ ▶ npm test 0:41 │ ☰ 3/5 │ 置信 中
⚠ 需要你: 权限确认 Bash: rm · 已等 0:37                    ← Claude 在等你时，状态栏换成这一行
⏱ ETA · 上次 6:12 (预测 5–9m ✓) · 已学习 57 次              ← 空闲时显示这一行
```

## 为什么做这个

把任务交给 agent 之后，你不知道它是 2 分钟回来还是 20 分钟回来，所以什么正经事都不敢开始。
这个插件回答的就是这个问题："**接下来这段时间，我能不能放心离开？**"

- **完成（T_c）**：Claude 交还控制权之前还需要的时间，显示为一个区间（P50–P80），不是一个假精确的时间点。
- **可离开（T_a）**：距离下一次需要你还有多久。"需要你"包括授权请求、提问、审批计划，以及任务做完。
  显示的数字是保守的：有 80% 的把握在这之前不会需要你；历史越少，给的承诺越短。
- 原则是**看行为，不听它自报**。插件只观察 hooks 事件流，从不问模型"你做到百分之几了"。
- **自己决定信多少历史。** 估计器会用你自己的历史回测，自动选择"相似历史"和"按你的节奏校准过的先验"各占多少权重：
  历史少且杂时主要靠校准先验，积累多了再逐步转向相似历史。不需要手动调参。

设计细节、从讨论记录到 Claude Code 的映射、算法和验证数据都在 [DESIGN.zh-CN.md](DESIGN.zh-CN.md)。
和 Codex 版设计（`agent-eta-codex-handoff`）的逐项对照及交叉测试结果见 [CODEX_COMPARISON.zh-CN.md](CODEX_COMPARISON.zh-CN.md)。

## 安装

需要 Claude Code 2.1.2xx 或更新版本（在 2.1.280 上测试过），以及 `python3` ≥ 3.8（3.8 和 3.13 上测试过）。插件只用标准库，不需要 pip 安装任何东西。

**方式 A：本地 marketplace（推荐，可长期使用）**

```bash
claude plugin marketplace add JohnMing143/agent-ETA   # GitHub 仓库；也可以是解压后的本地目录
claude plugin install agent-eta@agent-eta
```

重启 Claude Code，然后在会话里运行：

```
/agent-eta:setup
```

setup 会做四件事：

1. 把 `~/.claude/settings.json` 里的 `statusLine` 指向 `~/.claude/agent-eta/statusline.sh`，每 5 秒刷新一次。
   改动前会先备份成 `settings.json.agent-eta-backup`。如果你原来已经有状态栏，它会保留下来，显示在 ETA 这一行的上面。
2. 把 `~/.claude/projects` 里的历史 transcript 导入成训练数据，这样第一天就能给出个性化的估计。
3. 历史满 10 次运行时，用它回测一遍，选出最适合你的收缩强度（见下文"自动调参"）。
4. 输出一份历史报告。

**方式 B：临时试用（不安装）**

```bash
claude --plugin-dir 路径/agent-eta/plugins/agent-eta
```

> 插件的规范不允许插件自己设置状态栏，所以才需要多运行一次 `/agent-eta:setup`。
> 插件升级后目录会变，但状态栏不用重新设置：每次会话启动时，hook 都会刷新 `~/.claude/agent-eta/plugin_root` 这个指针。

## 使用

| 你想要 | 做法 |
|---|---|
| 看当前任务还要多久 | 看状态栏 |
| 历史报告、预测准确度、其他会话在干什么 | `/agent-eta:eta`（也可以直接问 Claude"我能离开吗""其他会话还要多久"） |
| 在另一个终端或 tmux 面板盯着所有会话 | `python3 ~/.claude/plugins/…/agent-eta/scripts/eta.py watch`（`/agent-eta:eta watch` 会告诉你完整路径） |
| 检查安装是否正常 | `/agent-eta:setup doctor` |
| 卸载状态栏 | `/agent-eta:setup remove` |

状态栏各字段的含义：

| 字段 | 含义 |
|---|---|
| `⏱ 3:12` | 本轮 agent 的有效工作时间。等你处理授权或回答问题的时间不算在内 |
| `完成 ~4–9m` | 距离交还控制权：大概率 4 分钟（P50），保守 9 分钟（P80）。`↑`/`↓` 表示预测刚刚明显变长或变短 |
| `可离开 ~3m → 14:52` | 可以离开多久，以及对应的钟点。窗口一旦给出，到期时间就固定下来，刷新时不会往后推。如果 Claude 需要你，或者预测明显变差，窗口会被撤销。绿色表示 ≥5 分钟，黄色表示 1–5 分钟；不足 1 分钟时显示"随时可能需要你"。账本里累计满 100 个窗口、且违约率上界 ≤20% 之后，会在后面加 `✓` |
| `▶ npm test 0:41` | 正在运行的长工具调用。它的预计时长来自同一条命令在这个仓库里的历史耗时 |
| `☰ 3/5` | Claude 的任务清单进度（只有模型在用任务清单时才显示） |
| `⏳ 等后台 ×2` | Claude 在等后台子代理，子代理完成后会自动继续 |
| `置信 低/中/高` | 由相似历史的有效样本量（或校准先验用到的运行数）和区间宽度决定。只靠内置先验估计时显示为 `置信 低·先验` |

命令行（`scripts/eta.py`）：

```
eta.py status [--session ID]     # 详细视图（进度条、依据、可离开到几点）
eta.py watch  [--interval 2]     # 实时看板，列出所有会话
eta.py report [--days 30]        # 历史统计、窗口账本、回测（对照内置先验和 Codex 设计里的 B0 基线）、当前收缩强度
eta.py backfill [-v] [--force]   # 重新导入 transcript
eta.py tune                      # 立即按你的历史重新调参（平时会在后台自动进行）
eta.py eval [--curve] [--json]   # 学习到底有没有用：相对不学习的提升，带 95% 区间
eta.py doctor                    # 自检
eta.py setup [--lang zh|en] [--refresh 5] [--no-backfill] | --remove
```

## 数据与隐私

- 所有数据只存在本机的 `~/.claude/agent-eta/eta.db`（SQLite），插件不做任何网络请求。
- 记录的内容只有：prompt 的长度和类别，工具名，命令的**归类键**（例如 `npm test`、`curl`、`git push`），以及各种耗时。
  **不记录** prompt 原文、命令参数（参数里可能有 URL、token、密码）、文件内容和命令输出。
  归类键里的每个词都要过白名单（短的普通单词，不能含引号、`=`、`/`、`@`）；`bash -c "…"` 会解析到里层命令。
  这些都有测试覆盖：用一条带 Bearer token 的 curl 命令跑一遍，然后在数据库文件里搜那个 token，结果为 0。
- 数据库文件权限是 0600，所在目录是 0700。
- 删除 `~/.claude/agent-eta/` 目录即可清空全部数据。

配置文件在 `~/.claude/agent-eta/config.json`：

| 键 | 默认值 | 说明 |
|---|---|---|
| `lang` | `auto` | `zh` / `en` / `auto` |
| `safe_quantile` | `0.2` | "可离开"的风险水平。0.2 表示有 80% 的把握 |
| `compose` | `newline` | 与原有状态栏的拼接方式：`newline` 另起一行，`inline` 接在后面 |
| `show_idle` | `true` | 空闲时是否显示摘要 |
| `store_prompt_preview` | `false` | 设为 `true` 时保存每个 prompt 的前 80 个字，在详细视图里用来辨认是哪个任务 |
| `cold_start` | `estimate` | 设为 `unknown` 时，只有先验可用就不显示任何数字，这是 Codex 设计的做法 |

## 自动调参

估计器有两个会随使用自动调整的参数。

**K0**：相似历史要积累多少有效样本，才压过"按你的节奏校准过的先验"。
合适的值因人而异：几十次五花八门的运行，校准先验最准；几百次相似的运行，相似历史最准；使用习惯在变时，要更早相信历史。
所以插件用你自己的历史回放来选：每个候选值（3 / 8 / 20 / 50 / ∞）都在回放里预测一遍，每个预测点只能用当时已经结束的运行，
按状态栏实际显示的三个分位数（完成 P50、P80，需要你 P20）的对数 pinball loss 打分，取最低的那个。

**近期权重半衰期**：越早的运行权重越低，半衰期候选 0.5 / 2 / 7 / 60 天，和 K0 在同一次回放里一起选。使用习惯会变，有的人今天的运行比上个月的更有参考价值；更短的半衰期必须比最长的那个好 1% 以上才会被采用（候选越多越容易拟合噪声）。

**分位数重校准**：如果估算系统性偏长或偏短，就按你自己的实际结果（真实值落在每次预测分布的哪个位置）换一个读数位置，比如过去报 P50 时实际七成都更早结束，以后就从分布里更靠前的地方读 P50。同样按时间前瞻检验（每个点只用它之前已结束的运行学出来的映射），能降低损失才开启。

**SAFE_K**："可离开"有多保守。候选 0 / 2 / 6 / 15 / 40，在同一次回放里选：优先取回测违约率 75% 置信上界 ≤ 20% 的最宽松候选；没有的话，取承诺次数够多（≥20）、实测违约率最低且不超过 20% 的候选；样本不够时用默认值 6。
回放看不到导入历史里的授权弹窗，所以状态栏**真实给出过**的窗口是最后一道检查：最近 30 天的真实窗口**确实**违约偏多（违约率的 75% 下界超过 20%）时，每次重选都会比上次再保守一档，直到账本恢复。只是"不确定"不算——以前用上界判断，会把一份真实违约率 15% 的记录一路推到最保守，剩下的反而是过度自信的承诺。

调参之前（已结束的运行不足 10 次，导入的 transcript 也算）状态栏不给"可离开"承诺，显示"离开：待验证"：未调参的先验给出的承诺不可靠（见下文跨用户验证）。

- 历史满 10 次运行时第一次选择（setup 时会立即做一次），之后已结束的运行数每增长 10%（至少 5 次），Stop hook 会在后台起一个独立进程重新选，不阻塞 Claude。
- `eta.py report` 会显示当前 K0、半衰期、重校准、SAFE_K、选择时间和依据；`eta.py tune` 可以手动立即重选。
- **跨用户验证**：作者本人加上公开数据集 [trace-commons/agent-traces](https://huggingface.co/datasets/trace-commons/agent-traces)（原始 Claude Code 会话，CC-BY-4.0）里的 5 位贡献者，共 405 次运行。
  - 学习的价值在于"默认节奏不对"的人：一位单轮中位 52 秒、比默认快一倍多的贡献者（267 次）相对内置先验 **+27.7% [+19.2%, +35.6%]**，典型误差 ×4.05 → ×2.52，几乎全部来自节奏校准；接近默认节奏的人提升很小（−3% 到 +7%，区间含 0）——先验本来就合适，学习也不会变差。
  - 一轮开始时的时长对谁都难预测：校准后残差 σ≈1.3–1.4（50% 区间约 ×2.3 宽）。
  - "可离开"按时间回放（每次重新调参只看到过去，窗口像真实使用一样进入账本）：这 6 份历史 132 次承诺违约 16%；再加 5 份公开数据集（见下）268 次违约 29%；**11 份合计 400 次承诺违约 24.5%（95% 上界 28%），高于 20% 的目标**。有的历史在目标内（8%、17%、19%），有的不在（21%–45%）。几乎所有违约都是 Claude **提前干完了**，而且是在一轮刚开始时给出的"1 分钟"承诺：一轮的时长是"双峰"的（几十秒的快问快答 vs 几分钟的任务），对数正态模型低估了快的那一峰。在修好之前，以你自己的账本出现 ✓（100 个以上真实窗口且在目标内）为准。调参前不做承诺：未调参时的承诺违约 21%，其中一位 5 次里违约 3 次。
  - **模型之间有差异，但工作类型影响更大**。又找了 5 份公开的 Claude Code 会话数据（Fable 5 两份；一位真人加自动化任务、用 Fable 5 / Opus 4.8 / Sonnet 4.6；Kimi K2.6、MiniMax M3、MiMo V2.5 Pro 的自动化运行；共 1,676 轮）。去掉工具执行时间后，模型每一步 Claude 系列 7–16 秒、MiniMax M3 17 秒，Kimi K2.6 约 100 秒但步数少得多；MiniMax M3 三分之一的轮次会停下来问你（Claude 1–10%）。但对交互式编码，内置先验在这些模型上都合适（P50 命中 51–57%）；让先验失准的是工作类型——一串几秒钟的小任务、或者大部分轮次不到一分钟的人——这时学习提升很大（+38% 到 +83%）。在按类别的节奏之外再加按模型的节奏：只在混用多家模型的历史上有小幅帮助（+1.4% [+0.6, +2.3]），在 Claude 系列内部反而略差（−1.5%），所以没有采用；短的近期权重半衰期已经能跟上换模型。
- `eta.py eval` 回答"学习到底有没有用"：按时间前瞻回放，和完全不学习的内置先验比，给出 95% 区间（按运行分组的 bootstrap），区间不含 0 才算"已证实"；还按当时已有的历史量分段；`--curve` 会画学习曲线，估计再多攒历史的边际收益。作者本机 67 次真实运行：整体 +7.4% [−0.3%, +13.7%]，最近三分之一 +14.0% [+3.4%, +22.0%]，更早的历史几乎没有可测的边际收益——提升来自最近的上下文和重校准，而不是更长的记忆。
- 做过严格的前瞻检验（只用"过去"选参数，在"未来"的点上评估）：6 组数据里有 5 组和事后最优的固定值只差 0–2%，使用习惯漂移的那组差 9%；在小样本和真实历史上比 v0.2 的固定值好 11–18%。

## 已知限制

- **刚开始预测很粗。** 用作者本机 38 次真实历史回测：v0.3 的 pinball loss 是 109，内置先验 113，B0 基线 149（低 27%，过了 Codex 的 10% 门槛）；v0.2 的纯学习版是 133，比内置先验还差。但 P50 的典型误差仍是 ×2.3（内置先验 ×2.1），这么少又这么杂的历史，谁都很难准。模拟数据积累到 240 次后，误差降到 ×1.3，pinball loss 比 B0 低 45%。报告里始终同时列出"当前""内置先验""B0"三组数字，方便对照。
- **"可离开"在账本验证通过之前都是"未验证"。** 真实历史上的回测违约率从 v0.2 的 29% 降到 11%（目标 ≤20%），但只有 18 次承诺，样本还太少。
- **授权请求的频率只能从实时使用中学。** transcript 里不记录授权弹窗，所以导入的历史数据没有这部分信息。
- Claude 5 系列模型（Opus 5、Sonnet 5 等）默认不提供任务清单工具（TaskCreate/TodoWrite），所以 `☰` 大多数时候不会出现。预测本身不依赖它。
- **Windows 未经测试。** hooks 调用的是 `python3`，Windows 上可能不存在；CI 里 Windows 只作为实验项运行。

